## 처리 구조와 실제 확인

- 기출: RAW 421문항과 CSV 421행 연결. 한 강의의 검색 예시에서는 40개 후보, 첫 20문항 패킷은 JSON 포함 22,769자였다. 전체 기출을 모델에 반복 입력하지 않고 ID로 원문을 조립한다. 이 수치는 특정 입력의 검색 예시이며 완전한 관련 문항 재현율 또는 청구 토큰 절감률이 아니다.
- 녹음정제: 기본 6,500자 구간, 교안 후보 5개×발췌 1,000자, 직접 조회는 다음 offset으로 이어 읽는다. 합성 3,894자/61타임스탬프를 35개 작은 청크로 나눠 정확히 재조합했고, 타임스탬프 경계 600개 합성 검사를 통과했다.
- 정리본: PART 2를 한 번 분리하고 JSON 편집 원본을 DOCX/PDF 생성에 재사용한다. PDF 변환은 새 작업 위치에서 수행하고 변환 실패 뒤 과거 PDF를 성공으로 보고하지 않는다.
- 질문/해설: 로컬 문항 인덱스와 근거 인덱스에서 선택한 문항·그림·주변 구간만 반환한다. 강의록과 Script 검색 결과를 구분하며 PART 2 요약을 교수의 직접 발언으로 인용하지 않는다.

## 의도적 차이와 검증 한계

- 정리본 기본 글꼴은 이번 Word/PDF 환경에서 확인한 **Malgun Gothic**이다. 이전 RIDIBatang-9 OTF는 Word가 대체하는 현상이 있어 기본값으로 쓰지 않았다. 두 형식에 같은 글꼴을 적용하고 실제 PDF에서 MalgunGothic/MalgunGothicBold를 확인했다. 원본 글꼴과 라이선스는 선택 사용용으로 보존하며, 다른 환경에서는 설치된 한국어 글꼴을 지정하고 출력 확인이 필요하다. 원본 스킬과 완전히 같은 서체라고 주장하지 않는다.
- 실제 전체 강의의 의미 교정, 전체 기출 Word 재생성, 실제 공통사진의 전수 독립 검수, Obsidian 앱 화면, 실제 Google Drive 업로드는 이번 시험 범위 밖이다. Drive 목적지와 연결은 친구 환경에서 지정해야 한다.
- `yama-word-obsidian`은 정방향 변환에 집중한다. 원래 Skill의 역변환·사진 Indication 부가 기능은 이번 파이프라인 범위에 넣지 않았다.
- Windows Word 파일 API로 실측/변환을 확인했다. 다른 OS/LibreOffice 경로의 동일 레이아웃은 별도 확인이 필요하다.
- 초기 변환 실험 뒤 숨은 Word 프로세스 2개의 소유를 확정하지 못해 임의 종료하지 않았다. 최종 변환기는 새 인스턴스의 소유를 확인하고 해당 인스턴스만 종료하며, 최종 검사는 이 경로로 수행했다.
- 패키지 버전은 사용자가 지정하지 않아 생략했다. Claude strict 검증은 이 경고를 실패로 취급하며 일반 검증은 통과한다.
- 실제 청구 토큰 사용량 절감률을 측정하지 않았다. 테스트는 의미 보존이나 출력 품질을 모든 자료에 대해 보증하지 않는다.

# Obsidian 해설 형식

`answers.json`은 작업 파일이다. `comment_lines`에 3–8줄을 넣고 각 줄을 `**수업 주제**`, `**시험 포인트**`, `**자료 안내**` 중 하나로 시작한다. 학습에 필요한 Word 편집자 안내는 자료 안내에 반영한다. `answers`에는 선택 범위의 각 `qid`를 한 번씩 넣는다. 불확실하게 추정된 문항 유형은 `type`에 객관식·단답형·보기형·서술형·매칭형 중 검토한 값을 지정할 수 있다.

```json
{
  "comment_lines": ["**수업 주제** — 적용 범위", "**시험 포인트** — 판정 기준", "**자료 안내** — 복기 연도"],
  "answers": [
    {
      "qid": "q001",
      "status": "자료 기반 풀이",
      "answer_lines": ["**①** — 결론과 문두에 맞는 이유."],
      "options": [
        {"marker": "①", "verdict": "O", "reason": "첫 선지의 성질과 판단 이유."},
        {"marker": "②", "verdict": "X", "reason": "둘째 선지의 성질과 판단 이유."}
      ],
      "concept_lines": ["선지 판정에 적용한 개념."],
      "evidence": [
        {"role": "lecture", "source": "교안.md", "location": "p.4 / 줄 36", "text": "해당 자료의 문구."}
      ]
    }
  ]
}
```

- `status`에는 `공식 답안`, `교수 직접 답변`, `자료 기반 풀이`, `정답 불확실` 중 하나를 쓴다. 출처 종류는 `lecture`, `script`, `official`, `textbook`이다. 공식 답안이나 교수의 직접 답변은 대응 출처를 포함한다.
- `options`는 원문 선지의 마커와 순서를 따른다. 주관식이면 `[]`로 둔다. 선지 판정을 확정할 수 없으면 `?`와 그 이유를 쓴다. 미복기나 자료 부족은 `gap_lines`에, 자료가 상충하면 `conflict_lines`에 판단 근거와 결론을 쓴다. 각 항목을 한 물리적 줄로 유지한다. 비교표는 행별로 줄을 나눈다.
- 기본 구조는 공지와 정리 Comment, 섹션, `[!question]`, `[!answer]- 해설`이다. 해설 안에 답안, 핵심 개념, 접힌 근거를 둔다. 한계나 출처 충돌이 있을 때 주의 상자를 표시한다. 문항·해설은 같은 깊이의 개별 상자다. 공통지문·보기는 문항 안에 둔다.
- 내장 그림의 원본 바이트를 `동봉 이미지/`에 복사한다. Word의 검토된 공통사진은 부모 상자에서 한 번 표시하고 각 문항의 참조를 보존한다. 문항별 그림과 공통사진 원본은 원래 Word에서도 확인할 수 있다.

# 녹음정제 도구와 파일 규격

스킬 폴더에서 아래 명령을 실행한다. Python 표준 라이브러리만 사용한다. 예시 파일명과 경로를 작업에 맞게 바꾼다.

## TXT 분할과 교안 조회

```text
python -X utf8 scripts/transcript.py split "녹음.txt" "작업"
python -X utf8 scripts/transcript.py lecture "교안.md" --terms "frontal bone" "orbit" --limit 4
python -X utf8 scripts/transcript.py lecture "교안.md" --page 9 --max-chars 3500
```

- `split`은 새 작업 폴더에 `raw/0001.txt`부터 순서대로 쓴다. 각 파일의 내용은 디코딩한 원문의 연속 구간이다. 기본 상한은 6,500자다. 문장 끝과 공백을 우선하되 가능한 경계가 없으면 긴 단어도 잘릴 수 있다. UTF-8을 기본으로 읽는다. 다른 인코딩을 확인한 경우 `split`과 `assemble` 모두 같은 `--encoding`을 전달한다.
- `lecture --terms`는 후보 페이지의 일부 문맥만 돌려준다. `top_score_page_count`가 2 이상이면 검색 점수가 같은 페이지가 있다. 1이어도 실제 발화가 그 페이지를 설명했는지 확인한다. 교안 제목·희귀 용어·숫자 등을 조합해 검색한다. 음역된 용어는 주변 발화에서 검색 단서를 찾는다.
- `lecture --page`는 `<!-- page N -->`의 실제 번호를 받는다. `next_offset`이 있으면 해당 값을 `--offset`으로 넘겨 나머지 구간을 확인할 수 있다. 그림 라벨이나 표 위치가 쟁점이면 그 페이지의 원본 화면을 확인한다.
- RAW MD에 페이지 마커가 없다면 파일 안에서 용어를 검색한다. 페이지 근거를 얻을 수 없으면 태그 상태를 보고하고 `--no-page-tags`로 조립한다.

## 작업자 파일

작업자마다 기본 청크 하나를 배정한다. 확인된 과목·주제와 교안 경로를 제공한다. 이웃 청크는 경계의 의미를 파악하는 데 필요한 앞뒤 구간만 읽는다. 교정 파일에는 배정 구간의 발화만 쓴다.

`작업/polished/0001.md` 등에는 첫 줄에 연결 방식을 쓰고, 바로 다음 줄부터 교정 본문을 쓴다. 코드 펜스를 붙이지 않는다. 연결 방식은 앞 청크의 마지막 발화와 해당 본문 사이에 적용된다.

| 첫 줄 | 쓰는 경우 |
| --- | --- |
| `<!-- join: start -->` | 첫 발화가 있는 청크 |
| `<!-- join: paragraph -->` | 새 주제 또는 새 단락 |
| `<!-- join: space -->` | 같은 단락에서 다음 어절·문장으로 이어짐 |
| `<!-- join: tight -->` | 한 어절이나 기호 안에서 잘린 경계 |
| `<!-- join: empty -->` | 타임스탬프·공백만 있는 청크. 본문은 비운다. |

작업자는 원문과 교정문을 대조한다. 의미 있는 발화, 부정, 조건, 예외, 숫자·단위, 고유명사, 예시, 강조의 순서와 내용을 확인한다. `작업/topics/0001.md` 등에 PART 2에 사용할 핵심 내용과 실제 시험 발언, 교안에서만 확인한 정보, 미해결 사항을 남긴다. 완료 보고에는 청크 번호, 파일 경로, 변경 판단이 필요한 부분, 검토 결과를 담는다.

## 페이지 검토

태깅 ON이면 발화가 있는 각 청크의 `작업/pages/0001.tsv` 등을 작성한다. 첫 줄에는 `# reviewed`를 쓴다. 모호한 구간이 남으면 `# unresolved` 다음에 탭과 간단한 사유를 쓴다. 이어지는 각 줄은 **본문 줄 번호, 실제 페이지 번호, 상태, 근거**를 탭으로 구분한다. 확인한 페이지 전환이 없으면 상태만 기록할 수 있다.

```text
# unresolved	교안 12·13쪽에 같은 표 제목이 있으며 전환 발언을 특정하기 어려움
1	9	confirmed	9쪽 도표의 고유 라벨과 첫 발화가 일치
6	11	uncertain	11쪽의 예시를 설명하나 전환 문장이 불명확
```

- 줄 번호는 연결 지시를 제외한 교정 본문의 1부터 시작한다. 본문 바깥의 빈 줄은 제외하고 내부의 빈 줄은 센다. 기존의 비어 있지 않은 줄을 고른다. 앞 청크와 이어지는 문장의 첫 줄은 태그 위치로 사용하지 않는다.
- `confirmed`는 실제 전환점, `uncertain`은 특정 쪽의 근거는 있으나 전환이 흐린 경우다. `skipped`는 교수의 말로 생략 범위와 번호를 확인한 경우다. 다음 발화 줄 앞에 적고, 같은 줄의 실제 전환 행보다 먼저 둔다.
- 이웃 청크의 전환과 중복되는 경우 두 청크의 근거만 대조해 태그 위치를 확정한다. 명확한 전환이 없는 청크는 검토 상태만 남긴다. 분할 경계나 정렬 순서만으로 쪽수를 매기지 않는다.

## 조립과 결과 확인

작업자가 작성한 PART 2의 본문을 `파트2.md`에 저장한다. 도구가 제목과 두 PART의 헤더를 추가한다.

```text
python -X utf8 scripts/transcript.py assemble "녹음.txt" "작업" "파트2.md" "강의 녹음정제.md" --title "과목 강의 주제 날짜" --lecture "교안.md"
```

교안 없이 조립할 때는 `--lecture`를 생략한다. 태깅 OFF를 지정할 때는 `--no-page-tags`를 넣는다. 도구는 입력과 기존 결과를 덮어쓰지 않는다.

- `page_review`가 `partial` 또는 `no-matches`이면 미해결 범위와 근거를 함께 전달한다. `reviewed`는 검토 파일이 모두 있으며 미해결 표시가 없는 상태다.
- 두 섹션의 헤더는 `## PART 1 — 교정 스크립트 (순수 정제)`, `## PART 2 — 강의 정리본 (녹음본 요약)`이다. PART 2는 두 번째 헤더 바로 뒤부터 파일 끝까지이며 `---`와 주제 헤더를 포함할 수 있다. `transcript-pdf-study`에는 조립한 Markdown과 해당 교안을 전달한다.
- 작업 폴더는 중간 결과와 검토 근거로 보관한다. 새 사용에서 다른 경로를 고른다.

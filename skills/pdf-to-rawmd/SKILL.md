# PDF / PPTX → RAW MD

[RAW_MD_STANDARD.md](references/RAW_MD_STANDARD.md)의 형식과 폴더 구조로 원본을 전사한다. 강의록마다 전용 폴더를 새로 만들고 RAW MD와 해당 강의록의 `동봉 이미지/`를 함께 둔다. 명령 예시는 이 스킬 폴더를 기준으로 한다. Python 환경에 PyMuPDF, python-pptx, Pillow가 필요하다.

## 1. 범위 배정

Main은 원본 경로, 페이지 범위, 출력 상위 폴더를 확인한다. 그 아래에 원본 파일명에서 확장자만 뺀 이름의 강의 폴더와 내부 `동봉 이미지/`를 먼저 만든다. 같은 이름의 폴더가 있으면 `_2`, `_3`처럼 사용하지 않은 접미사를 붙인 새 폴더를 선택한다. 여러 강의록을 한 번에 처리해도 각각 분리한다. 임시 작업 폴더는 따로 만들고 로컬 도구로 페이지 수와 분할 범위를 구한다.

```text
python scripts/rawmd.py plan INPUT --pages 1-30
```

전체를 변환할 때는 `--pages`를 생략한다. 작업자 한 명에게 최대 15페이지를 배정한다. 복잡한 범위는 `--size`로 더 작게 나눈다. 15페이지 이하도 새 작업자에게 맡긴다. 각 범위에는 이전 대화나 작업 결과를 상속하지 않는 새 컨텍스트를 사용한다. Codex에서는 `spawn_agent`의 `fork_turns="none"`을 지정한다.

Main은 작업자에게 역할, 입력 절대 경로, 담당 원본 페이지 번호, 전용 작업 폴더, 저장할 작업 파일, 이미지 저장 위치와 파일명 접두어, 이 스킬과 형식 기준 경로를 전달한다. 이미지 접두어 `slug`는 원본 stem의 공백·특수문자를 `_`로 바꾸고 40자로 줄여 한 번 정한다. 기존 파일과 충돌하면 출력명 또는 접두어에 일관된 접미사를 붙인다. 작업자별 출력 페이지와 이미지 파일명은 겹치지 않게 배정한다. 새 작업자를 실행할 수 없으면 검증할 수 없는 범위와 이유를 보고한다.

Main은 작업 전반에서 페이지·파일·상태 메타데이터만 받는다. 원문, 초안·최종 본문, 추출 상세 자료, 이미지와 근거가 섞인 QA 기록은 담당 작업자가 로컬에서 읽는다.

## 2. 변환 작업자

1. 담당 범위의 초안과 확인용 자료를 한 번에 만든다. 추출된 원문·서식·표는 그대로 활용하고, 실제 원본과 대조해 필요한 부분을 고친다. 자동 초안에는 수식·스캔·복합 개체나 그림의 내용이 빠질 수 있다. PPTX일 때만 [PPTX.md](references/PPTX.md)를 읽는다.

   ```text
   python scripts/rawmd.py draft INPUT --pages 1-15 --out JOB/chunk_01.md --packet JOB/chunk_01.txt
   ```

   `packet INPUT --pages 1-15`로 담당 텍스트와 서식·위치·검토 후보를 다시 조회할 수 있다. 초안과 packet 중 하나를 주 입력으로 선택해 페이지를 묶어 읽고, 다른 파일에서는 불확실한 페이지나 서식만 확인한다.

2. 원본 페이지의 읽기 순서와 의미 있는 시각 정보를 확인한다. PDF에서 이미지·벡터 후보는 `figures INPUT --pages 1-15 --out-dir JOB/candidates`로 얻을 수 있다. 원본에서 확인한 후보만 채택한다. 전체 화면의 개요로 배치를 보고 작은 글자·레이블·화살표·의심 부분만 확대한다. 작업자와 검토자는 기존 렌더를 재사용한다. 스캔이나 이미지 속 텍스트는 원본 화면에서 전사한다. OCR을 썼으면 원본과 대조한다. 판독이 불가능한 위치에 형식 기준의 불명확 표시를 넣는다.

   ```text
   python scripts/rawmd.py render INPUT.pdf --pages 6 --out-dir JOB/render
   python scripts/rawmd.py render INPUT.pdf --pages 6 --out-dir JOB/detail --box 10,20,300,420 --dpi 240
   python scripts/rawmd.py crop IMAGE.png --box 10,20,300,420 --out CROP.png
   ```

   PDF `render`는 `page_NNN.png`를 저장한다. 단일 페이지에 쓰는 `--box`는 회전이 반영된 페이지의 왼쪽 위를 원점으로 하는 pt 좌표다. `crop`은 PNG 왼쪽 위를 원점으로 하는 정수 px 좌표를 받는다.

3. 전체 담당 페이지에서 텍스트·표·수식·강조·그림의 관계를 원본과 대조한다. 채택한 PNG를 형식 기준의 파일명으로 저장하고 대응 Figure 아래에 임베드한다. 페이지 마커와 임베드 실존 여부를 확인한다. 컨텍스트가 부족하면 완료한 페이지까지 저장하고 남은 페이지를 Main에 알려 새 작업자가 이어받게 한다.

완료 보고는 `상태 | 작업 파일 경로 | 완료 페이지 | 표·그림 수 | 검증 결과 | 미해결 페이지·이유` 한 줄로 보낸다.

## 3. 독립 검토와 결합

1. Main은 변환을 맡지 않은 검토자에게 새 컨텍스트로 최대 15페이지씩 배정한다. 검토자는 원본과 작업 파일을 대조해 **담당 전 페이지, 모든 표, 모든 학습 Figure**를 확인한다. 텍스트·순서·강조·수식, 표의 행·열·셀 병합, Figure의 레이블·관계·실제 크롭과 임베드를 확인한다. 자동 텍스트 검사와 이미지 후보는 검토를 보조한다. 검토자는 이미 있는 렌더를 활용하고 필요한 부분만 추가로 확대한다.
2. 검토자는 문제 페이지, 위치, 수정할 내용, 판독·렌더의 한계를 QA 기록에 남긴다. Main에는 검토한 범위·문제 페이지·QA 기록 경로만 보낸다. 수정 작업자는 지적된 부분을 고치고 검토자는 수정한 부분과 인접 영향 범위를 다시 확인한다. 미해결 범위는 새 작업자에게 배정하거나 원본의 한계와 함께 보고한다.
3. Main은 독립 검토를 확인하고 채택한 PNG를 해당 강의 폴더의 `동봉 이미지/`에 둔다. 로컬 코드로 작업 파일을 원본 순서대로 결합해 같은 강의 폴더에 `[원본파일명(확장자 제외)]_rawmd.md`로 저장한다. 상위 폴더의 공용 이미지 폴더를 사용하지 않는다. 원본, 기존 MD, 기존 이미지는 사용자 승인 없이 덮어쓰거나 이동·삭제하지 않는다.

   ```text
   python scripts/rawmd.py merge INPUT --chunk JOB/chunk_01.md --chunk JOB/chunk_02.md --out "LECTURE_DIR/INPUT_STEM_rawmd.md" --pages 1-30 --slug SLUG
   python scripts/rawmd.py validate INPUT "LECTURE_DIR/INPUT_STEM_rawmd.md" --pages 1-30 --slug SLUG
   ```

   기계 검증은 페이지 번호·누락·중복, UTF-8, 임베드 경로·실제 PNG를 검사한다. 종료 코드와 경고를 모두 확인한다. Figure에 이미지가 없거나 이번 실행의 이미지가 참조되지 않으면 해당 페이지를 다시 확인한다. 최종 답변에는 산출물 경로, 페이지·그림 수, 독립 검토 결과와 남은 문제를 적는다.

## 4. 임시 파일

임시 파일은 자동 삭제하지 않는다. 정리가 필요하면 이번 실행이 소유한 임시 경로만 정리하는 PowerShell 스크립트와 사용자 실행용 `.cmd`를 제공한다. 정리 대상은 실제 삭제 없이 확인한다. 원본, 최종 MD, 참조 이미지, QA 근거는 보존한다.
